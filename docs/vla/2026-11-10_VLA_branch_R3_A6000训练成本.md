# VLA branch R3：在 8 卡 A6000 上全量微调的成本

**日期：2026-11-10｜来源：R3 检索 agent 的报告，原样保存（英文）｜对应 [Pipeline v2](2026-11-10_VLA_branch_Pipeline_v2.md) 第 4.3 节**

**结论：** v2 按"8 卡 A6000 全量微调 4B 模型"做的计划放不下。

- **单次训练成本：** 按官方 LIBERO 配方，单次训练加评测大约要：
  - starVLA-GR00T：340 GPU 小时，在这台服务器上约 42 小时；
  - π0.5：600 GPU 小时，约 75 小时。
- **整个计划：** 8 个配置 × 3 个种子 × 2 个 benchmark，合计约 17k GPU 小时（starVLA，相当于这台服务器 90 天）或约 30k GPU 小时（π0.5）。
- **显存：** 在 48GB 显卡上全量微调 4–7B 模型，两个仓库都没有人做成过。starVLA 的维护者建议 48GB 显卡改用 Qwen3.5-0.8B。

所有数字都是 agent 的外推估计，需要在 V0 实测。

---

## R3: Cost of fully fine-tuning starVLA and π0.5 on LIBERO with 8× RTX A6000

**Bottom line.** One full LIBERO fine-tune plus evaluation should cost about **340 GPU-h (~42 h on the node) for starVLA-GR00T** and about **600 GPU-h (~75 h) for π0.5**. The plan of 8 configs × 3 seeds on two benchmarks comes to roughly **17k GPU-h (~90 days) for starVLA and ~30k GPU-h (~155 days) for π0.5** on this one server. Both totals are extrapolations. Without cuts the plan does not fit on one 8×A6000 box. Nobody has published measurements on A6000 or on PCIe-only multi-GPU for these models.

Labels: **[M]** measured or reported by others, **[C]** read from configs or code, **[E]** the agent's extrapolation. Code was read at starVLA `starVLA_dev` (shallow clone on 2026-11-10), openpi `215abfb`, and LeRobot `81b8c5b`.

### Estimate on 8× RTX A6000 [E]

Assumptions:

- **Per-GPU speed:** an A6000 runs at about 0.45 of an A100 (range 0.38–0.52). Based on bf16 154.8 vs 312 TFLOPS dense, memory bandwidth 768 vs 2039 GB/s, and Lambda's measurement that the A100 SXM4 is 1.92× faster.
- **PCIe penalty:** +15–35% step time, assuming 10–20 GB/s NCCL bandwidth (not measured).
- **Net effect:** about 0.36× A100 throughput (range 0.28–0.45).
- **A100 baselines:** starVLA uses #158's 72.2 samples/s on 8 GPUs; π0.5 uses 9–11 samples/s per A100.
- **Evaluation:** 10–20 s per episode, anchored on OpenVLA-OFT ≈13 s/episode on an A6000 (openvla#195).

| Per run (official LIBERO recipe) | starVLA-GR00T (3.84M samples) | π0.5 (7.68M samples) |
|---|---|---|
| Training, wall-clock | ~41 h (27–67) | ~74 h (52–106) |
| Training, GPU-h | ~330 (220–540) | ~590 (415–845) |
| Full LIBERO eval (2,000 episodes) | ~8 GPU-h, ~1 h wall on 8 GPUs | ~8–11 GPU-h |
| LIBERO-plus eval (10,030 episodes) | ~42 GPU-h (28–56) | same |

**The plan:** 24 runs on LIBERO-plus-scale data (2,238,036 frames, 8.2× LIBERO), each run keeping the LIBERO sample budget and evaluated on both LIBERO and LIBERO-plus; the second benchmark is assumed to need 24 runs at the same budget.

- **starVLA:** 24×380 + 24×340 ≈ **17k GPU-h**, about 90 days of the node.
- **π0.5:** 24×640 + 24×600 ≈ **30k GPU-h**, about 155 days.
- **If LIBERO-plus runs use 2× samples:** add about 8k (starVLA) or 14k (π0.5) GPU-h.

**Levers to bring this down:**

- freeze the VLM;
- use the smaller Qwen3.5-0.8B or 2B backbone;
- run π0.5 for 15K steps (CounterAlign saw convergence at 10–15K);
- screen with one seed, then run three seeds only on finalists;
- run LIBERO-plus evaluation only on finalists.

### Practical risks

1. **Memory.** Full fine-tuning 4–7B on 48 GB has never been shown for either repo. starVLA has no gradient checkpointing or LoRA. If ZeRO-2 at 16 per GPU runs out of memory, ZeRO-3 or gradient accumulation multiplies traffic over PCIe. Run a one-hour memory and throughput probe first. QwenGR00T is far lighter than QwenPI.
2. **Hard-coded NCCL settings.** starVLA scripts set `NCCL_SOCKET_IFNAME=bond0` and `NCCL_IB_HCA=mlx5_*`; unset them on a single box (#180).
3. **Data loading.** openpi multi-GPU runs were reported as I/O-bound with ~10% speedup (#600); stage data in `/dev/shm`.
4. **Recipe mismatches.** starVLA's step counts and epoch figure disagree, and LeRobot vs openpi differ in chunk size, state input, base checkpoint and episodes per task. Pin one protocol: 50 trials and fixed initial states.
5. **Headless EGL.** Set `MUJOCO_GL=egl` and `MUJOCO_EGL_DEVICE_ID=0` alongside `CUDA_VISIBLE_DEVICES`. openpi's Docker README assumes X11 (`xhost`). The LIBERO and LIBERO-plus installs conflict with each other. The A6000's graphics pipeline should help, since starVLA reports slow rendering on A-series datacenter GPUs (#168).
6. **CPU for eval.** LIBERO eval is CPU-bound, so plan at least 16 cores for 8–16 parallel workers.
