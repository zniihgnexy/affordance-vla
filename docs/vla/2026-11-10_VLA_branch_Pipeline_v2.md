# VLA branch Pipeline v2：用 affordance 计划与 episode 状态训练 VLA

**日期：2026-11-10｜分支：`vla`｜状态：研究设计，未做实验｜取代 [v1](2026-11-10_VLA_branch_检索清单与Pipeline_v1.md)**

标 **［我的决定］** 的是起草时我选定的默认值，可以改；其余内容已在 2026-11-10 的对话中与项目负责人确认。选型依据见[检索结果](2026-11-10_VLA_branch_检索结果_backbone_benchmark_近邻.md)。

## 0. 这一版改了什么

v1 把贡献放在 memory 模块上，主 benchmark 选的是记忆类 benchmark，VLA 只用 LoRA 接一下。这样和 `mem` 分支重叠，也没有把训练 VLA 当成核心。项目负责人明确了三点：

1. **VLA 训练是这条路径的必要部分。** 要证明的是：加了 affordance 等信息、按新方法训练出来的 VLA，比同一 backbone 按常规方法训练出来的仿真效果更好。
2. **必须和 `mem` 分开。** 贡献不能是"在现成 VLA 外面挂一个记忆模块"。
3. **memory 只保留一个轻量的 episode 内 affordance 状态。** episode 结束就清空，不做跨场景的持久记忆。

## 1. 研究问题与核心假设

**研究问题：** 在物体多、会被遮挡或被移动的桌面操作中，能不能通过改变 VLA 的训练方式来减少抓错物体、接近方向不对、碰撞这类错误？做法是让 VLA 先说清楚"在哪里接触、从哪个方向接近、大致怎么走"，并且一直记得目标物体在哪。

**核心假设（待验证）：**

- VLA 在杂乱场景中出错，一个原因是动作头没有和"在哪里接触、怎么接触"绑定。
- 另一个原因是目标被挡住或被移动之后，模型就丢了它。
- 如果在训练中做到下面三点，同一个 backbone 的闭环成功率会提高，而且这三类错误会减少：
  1. 让 VLA 预测一个统一的"接触点–接近方向–路径点"计划；
  2. 约束动作与这个计划保持一致；
  3. 给 VLA 一个 episode 内的轻量 affordance 状态。

**"4D" 在本分支的含义：** 3D 的 affordance 与接触几何，加上两个时间尺度。一个是动作块内的计划，说的是接下来几步怎么动；另一个是 episode 内的状态，记录之前看到过什么、动过什么。A4A 已经用 "4D affordance" 命名物体点的未来轨迹，论文里的命名要避开。

## 2. 和 `mem` 分支的分界

| | `mem` | `vla` |
| --- | --- | --- |
| 研究对象 | 环境记忆系统 | VLA 策略的训练方法 |
| 数据 | SceneFun3D、人类动作 | LIBERO 系列、RoboTwin 2.0 的机器人示范 |

本分支不使用 SceneFun3D、人类视频和 SMPL-X。

## 3. 方法

### 3.1 三个组成部分

1. **CAW 计划（Contact–Approach–Waypoint）。** 对当前要操作的目标，VLA 预测：
   - 接触点（3D）；
   - 接近方向（单位向量）；
   - K 个末端路径点，范围到下一次夹爪开合为止。

   affordance 部分预测的是目标物体和它的接触区域，接触点应该落在接触区域内。检索中还没有看到有工作把这三样合成一个表示放进 VLA。
2. **计划–动作一致性。**
   - 训练时，从预测的动作块推出末端路径，约束它贴近计划中的路径点；
   - 接触前的运动方向要贴近接近方向；
   - 接触点要落在预测的 affordance 区域内。

   ［我的决定］LIBERO 的动作是末端增量，累加就能得到路径，所以这个 loss 可微（需核实动作空间和缩放）。flow 动作头取单步去噪的动作估计来计算这个 loss。
3. **Episode affordance 状态（EAS）。**
   - 内容：每个被跟踪的物体一个槽位，记录最后已知的 3D 位置、affordance 特征、状态（可见、被挡、被抓、被移动）以及多久没看到。
   - 用法：编码成几个 token 送进 VLM。
   - 更新：每个动作块之后用本步的 affordance 预测、深度和相机参数更新。看得见就刷新；看不见又没被抓，就保留并标成"被挡"；被抓住的物体跟着末端移动。
   - ［我的决定］更新规则第一版用规则，只有编码器是学出来的；可学习的更新放到之后。

### 3.2 训练流程

```text
示范数据（LIBERO 原始 HDF5；RoboTwin 2.0）
   │  回放仿真状态，重新执行动作以取得接触
   ▼
自动标签：目标物体与接触区域、CAW 计划、每个物体每一步的 EAS
   ▼
VLA 训练（同一 backbone）
  输入：多相机图像 + 指令 + 本体状态 + EAS tokens
  VLM ──► affordance 头（目标 + 接触区域）
      └─► CAW 计划头（接触点、接近方向、K 个路径点）
  动作专家（flow）◄── 读取 CAW 计划的隐状态
  loss = 动作 + affordance + CAW + 一致性
```

［我的决定］CAW 用可学习的 query token 加回归头输出，而不是输出数字文本：一是速度快，二是一致性 loss 能直接反传。训练时的 EAS 用标签生成，并加入噪声和随机丢失，模拟感知误差；后期再用模型自己生成的 EAS 微调，以减小训练和测试之间的差距。

### 3.3 推理流程

```text
每个动作块：
  观察 + 指令 + 本体状态 + 上一步的 EAS
    → VLA 输出 affordance、CAW 计划和动作块
    → 执行动作块
    → 用本步的预测、深度和相机参数更新 EAS
  episode 结束：EAS 清空
```

可以读取的仿真信息沿用 v1 的约定：深度、相机内外参和本体状态可以用。第一版 EAS 可以用仿真给出的可见物体编号做关联，另外单独报告一行不用仿真分割的结果。不能读被挡住物体的位姿、未来状态和测试标签。

### 4.3 训练方式、算力与削减顺序［我的决定］

**训练方式：**

- 所有配置都全量微调 VLM、新增的头和动作专家，在 8 卡 A6000 上用 ZeRO-3 或 FSDP 分片。
- 基线和方法始终用同一种训练方式。
- LoRA 只用于快速初筛，不进主表。
- 粗估：4B 参数全量微调，Adam 状态加权重和梯度约 64GB，分到 8 卡上每卡约 8GB，再加上激活。具体以 V0 实测为准。

**算力（2026-11-10 确认）：**

| 设备 | 用途 |
| --- | --- |
| 远程 8 卡 A6000，随时可用 | 主力 |
| 5060 机器 | 仿真和可视化 |
| Isambard-AI | 正在申请，约 4,000 GPU 小时，只用于扩展。它是 ARM 架构，如果以后变成主力机器，backbone 改用 GR00T N1.7 |
| Mac | 阅读和查看结果 |

**如果 V0 估算超出预算，按以下顺序削减：**

1. B1–B3 的消融只跑 1 个种子，并且只用部分 suite；
2. 去掉 K3；
3. π0.5 只在 LIBERO-Plus 上跑 B0 和 B4；
4. RoboTwin 2.0 只用一部分任务（例如 50 个里的 10 个）。

**不能削减的：** LIBERO-Plus 上 B0 与 B4 的 3 种子对比，以及 K1。

**人手假设：** 按一名研究者加 agent 协助来排。先把 LIBERO 全部做完，RoboTwin 的标签工作等 V4 出现效果之后再开始。

## 5. 实验设计

### 5.1 配置（同一 backbone、同一份数据、同样的训练步数）

| 配置 | 内容 | 要回答的问题 |
| --- | --- | --- |
| B0 | 常规训练，只有动作 loss，代码与其他配置相同 | 基线 |
| B1 | 加 affordance 辅助头 | 对应 Wiring Matters、Afford-VLA，是审稿人会要求的低成本消融 |
| B2 | 加 CAW 计划头，动作专家读取计划，没有一致性 loss | 对应 ACoT-VLA、OASIS |
| B3 | B2 加一致性 loss | 计划与动作对齐有没有额外贡献 |
| B4 | B3 加 EAS（完整方案） | 遮挡和移动情形下状态有没有贡献 |
| K1 | 结构与 B4 相同，辅助目标打乱或置零 | 排除"只是参数变多了" |
| K2 | 真值 CAW 或真值 EAS 作为输入 | 上界，单独报告 |
| K3 | B4，但 EAS 不用仿真分割 | 对仿真信息的依赖有多大 |

**外部对照：** AffordanceVLA（π0，代码已开源）、ACoT-VLA（π0.5，代码已开源）、Afford-VLA（代码已开源），能复现就按我们的协议重跑。A4A 和 Pri4R 没有可用代码，只引用论文报告的数字并注明。

### 5.2 指标

- **主要指标：** 闭环成功率，包括总体和 LIBERO-Plus 每个扰动维度，以及 LIBERO-Occ、LIBERO-PRO、RoboTwin 2.0 Hard。
- **错误类型：** 从仿真状态自动判断以下几类，并人工抽查视频来验证判断规则：
  - 抓错物体：第一个接触或被抓的物体不是目标；
  - 方向错误：接触时的接近角与真值相差超过阈值，或接触点落在接触区域外；
  - 碰撞：机器人或手中物体与非目标物体发生超过阈值的接触；
  - 抓取失败；
  - 超时。

  检索中还没看到 affordance VLA 单独报告这些错误率，这可以作为贡献之一。
- **离线指标：** 接触点误差、接近角误差、路径点 ADE，以及 EAS 状态的准确率。
- **统计：** ［我的决定］主表每个配置至少 3 个随机种子，报告置信区间；初筛阶段可以只跑 1 个种子。

### 5.3 成功标准

- B4 在 LIBERO-Plus 总体和扰动子集上显著优于 B0，三类错误的比例下降；
- B1→B4 每一步都有可测的增益，或者能解释为什么没有；
- 同样的趋势在 RoboTwin 2.0 Hard 和 π0.5 上也成立；
- K1 不应复现 B4 的增益。

### 5.4 NeurIPS 2027 的必做范围［我的决定］

- **必做：** B0–B4、K1、K2；LIBERO-Plus 加 LIBERO-Occ 和 LIBERO-PRO；RoboTwin 2.0 Hard；至少重跑一个外部对照（AffordanceVLA 或 ACoT-VLA）；π0.5 上至少跑 B0 和 B4。
- **可选：** K3、其余外部对照、ICCV 版本。

**已经拥挤的方向：**

| 方向 | 已有工作 |
| --- | --- |
| 2D 轨迹作为视觉 CoT 或画在图像上 | MolmoAct、HAMSTER、TraceVLA、CoA-VLA |

| 用粗动作轨迹引导动作生成 | ACoT-VLA、OASIS |

**候选空白（未确认）：**

1. 统一的 CAW 表示；
2. 训练时可微的计划–动作一致性。CoRAct（2026-10-29）用奖励做离线对齐，DreamTrajectory 用测试时搜索，都要区分开；
3. episode 内的 affordance 状态。检索到的 31 篇工作都没有在 episode 内持续更新 affordance；
4. 按错误类型评测。

**审稿人最可能拿来对比的：** AffordanceVLA、A4A、ACoT-VLA。Wiring Matters 一定会被要求作为低成本消融。如果主张一致性，还会被要求和 CoRAct 比。

**来自 Wiring Matters 的提醒：** 简单联合训练反而掉分（85.5 对 93.1）；把真值 affordance 当输入也会掉分（88.3 对 94.0）。所以"怎么接"是关键，B2–B4 的连接方式需要专门消融。

| R8 | P1 | 投稿会议选择（沿用 v1 的 S9） | 见 v1 第 6 节 S9 |

## 9. 风险

1. **创新性偏增量。** 每个组成部分单独看都有近邻，贡献要靠组合，以及"哪个部分减少了哪类错误"的分析。R1、R4、R5 要尽早做。
2. **连接方式敏感。** Wiring Matters 表明，接法不对反而会掉分，要预留消融的算力。
3. **饱和。** LIBERO-Plus 的最好成绩一年内从 79.6% 涨到了 92.4%（汇总榜数据），所以 RoboTwin 2.0 Hard 不可省。
4. **算力。** 公开配方都基于 80GB GPU；主表约 8 个配置乘 3 个种子，再加第二 benchmark 和第二 backbone，V0 必须实测单次训练的成本。
5. **标签。** LeRobot 和 RLDS 版本可能没有仿真状态，要从原始 HDF5 重新生成；直接设置状态会绕过动力学，接触信息需要重新执行动作才能得到。
6. **RoboTwin。** 双臂机器人，所以 CAW 要按臂分开；SAPIEN 依赖 Vulkan，在 A6000 上还没测过。
7. **EAS 的训练与测试差距。** 训练时用标签生成的状态，测试时用模型自己生成的状态，需要做噪声增强和二次微调。
8. **代码变动快。** starVLA、GR00T 每周都在更新，要固定 commit。

## 10. 留给执行者决定的事

- 具体网络结构，K 的取值，EAS 的槽位数；
- 各个 loss 的权重和超参数；
- 标签和错误判断的阈值；
- 种子数之外的试验次数；
- notebook 的拆分方式。

## 11. R1、R3 结果对 v2 的影响（2026-11-10 补充）

详见 [R1 近邻全文核实](2026-11-10_VLA_branch_R1_近邻全文核实.md) 和 [R3 A6000 训练成本](2026-11-10_VLA_branch_R3_A6000训练成本.md)。

### 11.1 定位调整

六篇近邻都没有完整覆盖三个组成部分中的任何一个，按第 7 节的规则继续推进，但主张的轻重要调整：

| 组成部分 | R1 判断 | 调整后的说法 |
| --- | --- | --- |
| (b) 计划–动作一致性 | 最开放。CoRAct 用奖励在噪声空间对齐，不可微；Fast Plans 只做条件输入 | **作为主贡献**："训练时可微的计划–动作一致性" |
| (a) CAW 计划 | 每个部分都有人做过，但没人把它们合成一个 3D 表示 | "第一个统一的接触点–接近方向–路径点表示"，不说"第一个预测接触或路径点" |
| (c) episode 状态 | 空间很窄。ObjDream（2610.20223）在 LIBERO-Plus 和 RoboTwin 2.0 Hard 上做了 episode 内的物体槽，包含身份、几何和可见性；Ledger（2609.34554）用外部物体记录交给 LLM 规划器 | 作为辅助部分；必须对照 ObjDream 式物体槽和普通帧历史 |

**新增对照：** ObjDream 式物体槽、普通帧历史、CoRAct 式奖励对齐、Fast Plans 式条件输入（视可复现程度而定）。

**新增必读：** ObjDream、Ledger、Fast Plans Faithful Actions（2609.30833）、GAM（2609.23863）、HINT（2609.02653）。

**一处利好：** 六篇都没有报告抓错物体、方向错误或碰撞的比例，也都没有在 LIBERO-Occ、LIBERO-PRO 或 RoboTwin 2.0 Hard 上评测。

### 11.2 算力：第 4.3 节的默认值不成立

**R3 的估计：**

- 在 8 卡 A6000 上全量微调 4B 模型，两个仓库都没有人做成过。starVLA 不支持梯度检查点和 LoRA，维护者建议 48GB 显卡改用 0.8B。
- 按官方配方外推，单次 LIBERO 训练加评测：starVLA-4B 约 340 GPU 小时，π0.5 约 600 GPU 小时。
- 第 5.4 节的必做范围合计约 17k GPU 小时（starVLA），相当于这台服务器 90 天，放不下。

**可用的杠杆：**

- 换更小的 backbone。Wiring Matters 用的就是 starVLA QwenPI 加 Qwen3-VL-2B，可以直接对比。
- 冻结 VLM。
- π0.5 只训 15K 步。
- 先用 1 个种子初筛，只对入围的配置跑 3 个种子。
- LIBERO-Plus 的评测只给入围的配置做。

**待项目负责人决定：** backbone 的规模和训练方式。在这之前，V0 的第一件事是用一小时测一下 2B 和 4B 在 A6000 上的显存和吞吐。

### 11.3 R2：评测协议与算力的重新估计

详见 [R2 LIBERO 变体协议](2026-11-10_VLA_branch_R2_LIBERO变体协议.md)。

**协议：**

- LIBERO-Plus、LIBERO-PRO、LIBERO-Occ 都是测试集。
- 主结论采用最常见的做法：只用标准 LIBERO-40 的示范训练，然后在三个集合上 zero-shot 评测，各按官方次数：
  - LIBERO-Plus：10,030 个任务，每个 1 次；
  - LIBERO-PRO：每个任务 50 次；
  - LIBERO-Occ：2,000 个实例，发布版默认是每个任务 1 次，要改成 50。
- 在 LIBERO-Plus 自己的数据上微调，只作为附加消融。

**对设计的影响：**

1. **标签来源。** 训练数据就是原始 LIBERO 的 HDF5，回放就能得到深度、分割、物体位姿和相机参数。LIBERO-Plus 公开的训练数据没有仿真状态，不能用来提取标签。
2. **EAS 的评测要写清楚。** LIBERO-Occ 的遮挡物从第一帧就在，EAS 只有在目标后来变得可见时才可能有用。评测时按"目标是否中途出现"拆开报告；用了腕部视角，就要和 VIM 的 74.0 比，而不是 65.05。
3. **数据量不变。** 训练量保持在标准 LIBERO 的规模，R3 按 8.2 倍数据量做的估计不适用。

**重新估计（粗估，需 V0 实测）：**

- **单次成本：** 按 R3 的单次数字，starVLA-4B 每次约 330 GPU 小时训练，加上 LIBERO、Plus、PRO、Occ 四套评测约 100 GPU 小时，合计约 430 GPU 小时。
- **必做范围全跑 3 个种子：** 8 个配置，共 24 次，约 10k GPU 小时，相当于这台服务器 54 天。
- **加上初筛：** B1–B3 和 K3 只跑 1 个种子，共 16 次，约 7k GPU 小时，约 36 天。
- **换成 2B backbone：** 成本大约减半，具体以实测为准。
- **另外：** RoboTwin 2.0 和 π0.5 的部分另算。
