# 第 1 步（前半 ③）：旋钮的碰后动向由关节算；`mug_8` 的把手单独对齐

日期 2026-11-26；任务 AFFO-18（Pipeline v4 执行，AFFO-8）；分支 `agent/vla-engineer/affo-18`。只用 CPU，没有 GPU 作业，没有训练。接着 `docs/vla/2026-11-26_VLA_branch_第1步_交互map标签.md`（AFFO-15）第 5 节留下的两件事；做法来自 `docs/vla/2026-11-26_VLA_branch_泛化参考深核.md` 第 2 节的 c1（FlowBot3D 的关节公式）和 b2（AffordDP 对部件配准的思路），只借思路，没有装它们的代码。

## 1 三个问题的答案

1. **旋钮接触位置散布 32.9 cm 的原因：部件体的坐标原点不在旋钮上。** 修成“以被转动的那个旋钮的关节锚点为原点”后，散布 **2.02 cm**（跨厨房、留一个厨房的算法，259 次接触，57 个厨房）。见 §2。
2. **“碰到之后往哪个方向动”改成由关节算：四种部件能用同一个定义记下来，但旋钮的平移方向不能用，要用“转轴加正负号”。** 抽屉把手、柜门把手：能用，比旧记法更一致（0.73 → 1.00，0.91 → 0.98）。水龙头把手：能用（0.49 → 0.91），但新旧方向差得多（夹角中位 67°）。旋钮：接触点处的平移方向不能用（0.15）；转轴加正负号能用，按炉灶设计分开后跨厨房一致 0.85–0.93，整条示范的符号 259/259 一致。见 §3。
3. **`mug_8` 过线了：把手长度归一化（办法 1）+ ring 处理，落点率 0.84、闭合轴误差中位数 10.9°（线是 0.8 和 20°）。** 其余 4 个留出实例都没有变差（落点率不降，闭合轴误差各多 0.2–1.4°，仍在 13° 以内）；合计 0.94 / 12.0°。没有用留出实例的示范做对齐。plain 处理下 `mug_8` 仍不过（0.34）。办法 2（把手配准）也做了：ring 下 `mug_8` 落点率 0.87，但闭合轴误差 20.5°，没过线。见 §4。

## 2 旋钮为什么散布 32.9 cm（问题 1）

`TurnOffStove` 每条示范记一个“部件”：夹爪接触次数最多的名字里带 `knob` 的 body。数据来自 `extract_v1`，没有重放。

| 事实 | 数字 |
| --- | --- |
| 接触点到该 body 原点的距离（中位） | **49.3 cm** |
| 接触点到该 body 的关节锚点的距离（中位） | **2.05 cm** |
| body 原点到关节锚点的距离（中位） | 48.2 cm |
| 同一个炉灶上另一个旋钮：body 原点相距 / 关节锚点相距（中位） | 53.4 cm / 29.5 cm |
| 示范碰的旋钮和指令里的灶眼一致 | 259 / 259 |
| 57 个厨房里被碰过 ≥ 2 个不同旋钮的厨房 | 37（每厨房 1–5 个，共 128 个旋钮） |
| 被转动的关节是该旋钮自己的 hinge（`<body>_joint`） | 259 / 259，关节范围 0–3.14 rad |

- 结论（事实）：被转动的是**单个旋钮自己的 hinge**，部件体就是这个旋钮的 body；但 body 的原点离旋钮 49 cm，每个旋钮的偏移又不同。指令点哪个灶眼，示范就碰哪个旋钮，所以同一个“部件坐标系”里的接触位置随灶眼而变，散布成 32.9 cm。
- 修：以关节锚点为原点，朝向仍取部件体的朝向。散布 32.9 → **2.02 cm**（留一厨房）；按炉灶的三种设计分开：`stove` 156 次 2.01 cm，`stovetop` 92 次 1.64 cm，`widestove` 11 次 1.90 cm（修前 15.4 / 13.2 / 15.9 cm）。图 `knob_frame_before_after.png`：修后接触点分在旋钮两侧 ±2 cm。
- 同一个办法对别的部件不对：柜门的关节锚点是铰链（离把手约 45 cm），把手的接触位置仍以部件体原点为准（2.1 cm）。以哪个点为原点要按部件取，旋钮取锚点。
- 旋钮的朝向：`stove` / `widestove` 的旋钮在前面板，转轴水平（机器人底座坐标系里是 −x）；`stovetop` 的旋钮在台面，转轴竖直。这是两种炉灶设计，见 §3。

## 3 碰后动向由关节算（问题 2）

### 3.1 新的记法

- 滑动关节：动向 = 关节轴 × 符号。
- 转动关节：接触点处的动向 = 符号 × (轴 × r) / |轴 × r|，r 是从关节轴到接触点的垂直向量，只留方向（FlowBot3D 的公式，去掉长度）。另记“转轴 × 符号”：绕哪根轴、往哪边转。
- 符号 = 关节值变化的正负，两种窗口：接触后 1 秒（旧记法的窗口，变化不到 1e-3 记为没定义）；或到整条示范结束（总是有定义）。
- `extract_v1` 的事件里已有关节的类型、轴、锚点和三个时刻的关节值，所以没有补提取，没有新建 `extract_v2`。代码 `affordance_vla/plan/rc365_joint_labels.py`。

### 3.2 新旧并排（同一批示范，pretrain + target）

一致程度 = 跨厨房（留一个厨房）、在部件坐标系里、与其他厨房均值方向的夹角在 30° 内的比例，旧记法也是这个算法和容差。符号取接触后 1 秒窗口。

| 任务（部件） | 示范 / 厨房 | 关节 | 离轴距离 r 中位 | 有定义 旧 → 新 | 一致程度 旧 → 新 | 新旧夹角（两者都有定义的 n） |
| --- | --- | --- | --- | --- | --- | --- |
| `OpenDrawer`（抽屉把手） | 322 / 50 | 滑动 | 1.7 cm | 0.77 → 0.75 | 0.73 → **1.00** | 中位 11°，≤30° 79%（210） |
| `OpenCabinet`（柜门把手） | 257 / 55 | 铰链 | 44.6 cm | 0.86 → 0.94 | 0.91 → **0.98** | 12°，94%（213） |
| `TurnOnSinkFaucet`（水龙头把手） | 257 / 54 | 铰链 | 5.6 cm | 0.38 → 0.93 | 0.49 → **0.91** | 67°，14%（92） |
| `TurnOffStove`（旋钮，平移方向） | 259 / 57 | 铰链 | 1.9 cm（20% 在 1 cm 内） | 0.26 → 0.88 | 0.01 → 0.15 | 71°，23%（53） |

整条示范符号（`window_end`，总有定义）：抽屉 1.00、柜门 1.00、水龙头把手 0.83（有定义 0.98）、旋钮的平移方向 0.02。

### 3.3 转轴 + 正负号（旋钮、水龙头把手）

| 任务 | 符号（接触后 1 秒：负 / 没动 / 正） | 符号（整条示范：负 / 正） | 转轴×符号一致（部件系，1 秒 / 整条） |
| --- | --- | --- | --- |
| `TurnOffStove` 合计 | 200 / 32 / 27 | 259 / 0 | 0.00 / 0.38 |
| `stove`（前面板，156） | 109 / 28 / 19 | 156 / 0 | 0.85 / **1.00** |
| `stovetop`（台面，92） | 83 / 3 / 6 | 92 / 0 | 0.93 / **1.00** |
| `widestove`（前面板，11） | 8 / 1 / 2 | 11 / 0 | 0.80 / 1.00 |
| `TurnOnSinkFaucet` | 220 / 18 / 19 | 210 / 42 | 0.92 / 0.83 |

- 旋钮合计的一致程度是 0，不是因为转法乱，而是两种炉灶的转轴不同（前面板水平，台面竖直），均值落在两者之间，谁都不在 30° 内。按设计分开后整条示范符号 100% 一致：“关”这个动作对每个旋钮都是关节值减小。
- 事实：接触后 1 秒内，旋钮关节有 27 次往正向动（10%）、32 次没动。**推断**：夹爪刚碰到时旋钮被带得晃了一下，或示范者先往回拨；没有逐条看。整条示范的符号不受影响。

### 3.4 结论：旋钮和水龙头把手能不能用

- **水龙头把手：能用。** 新记法有定义 0.93、一致 0.91（旧 0.38 / 0.49）。问题是新旧方向差很多（夹角中位 67°，只有 14% 在 30° 内）：旧记法的夹爪位移里有沿关节轴方向的分量（均值 0.6），而沿轴的位移不会转动手柄。**推断**：夹爪在手柄上一边拨一边沿轴滑。新记法描述的是“部件怎么动”，不是“夹爪怎么动”；后面的动作头训练该跟哪个，要在第 1 步后半的方案里定。整条示范里 42 条（17%）往正向转，210 条往负向、5 条没动；**推断**：水龙头可以往冷 / 热两侧开，没有核实。
- **旋钮：接触点处的平移方向不能用，转轴 + 正负号能用。** 接触点离轴只有 1.9 cm（20% 小于 1 cm），平移方向跨厨房只有 0.15 一致（旧记法 0.01）。这时按任务书的做法以转轴加符号为准：按炉灶设计分开，整条示范符号 100%、1 秒窗口 0.85–0.93 一致。代价：转轴在部件系里随炉灶设计而定，使用它要知道（或由图像判断）旋钮在前面板还是台面。
- 抽屉、柜门：同一个定义够用，新旧方向接近（11–12°），比旧记法更一致，没有出现要查的偏差。柜门有 6% 的示范新旧差大于 30°（例如 `OpenCabinet` ep3，95°），没有逐条查原因。

图：`report/media/weekly_2026_11_23/label_followups/<任务>_ep*.png`（接触点红、关节方向绿、夹爪方向橙、关节轴青；抽屉 2 张、柜门 3 张、水龙头 2 张、旋钮 3 张，旋钮含两种炉灶）和 `part_label_comparison.png`。

## 4 `mug_8`：把手单独对齐（问题 3）

### 4.1 做法

类别坐标系里（身高和身体半径各归一为 1，把手朝 +x），把 x > 1.05 的点算作把手；把手伸出量 = 最远点的 x − 1.05。`mug_8` 的伸出量 1.30，12 个源实例 0.48–1.18（中位 0.92）。只动搬运之前的对齐，最近点搬运、ring 处理、检查沿用 AFFO-15 的代码（`category_transfer.py`、`transfer_check.py`、`rc365_symmetry.py`）。代码 `affordance_vla/plan/handle_align.py`。

- **办法 1（`length`）：** 每个实例（源和目标）的把手沿 +x 缩放到源实例的中位伸出量，身体不动。
- **办法 2（`registered`）：** 目标的把手点对源实例的把手点云（合并）做 ICP，每个坐标轴各自的缩放和平移（不旋转），20 次迭代，只变换把手点，源不动。
- 对齐只读留出实例的表面点（伸出量、ICP 的点）。留出实例的示范只用于打分；`tests/plan/test_handle_align.py` 里有一条测试，对齐结果不依赖抓取。闭合轴不随对齐变形（源和目标都按原来的类别坐标系变换）。

### 4.2 结果

12 个 pretrain 源实例 → 5 个留出实例，503 次抓取。每格是落点率 / 闭合轴中位误差；线是 0.8 和 20°。`none` 两行与 AFFO-15 的 plain、ring 逐项相同（脚本重新算出，不是抄的）。

- **`mug_8` 过线：办法 1 + ring，0.84 / 10.9°。** 其余 4 个：落点率 mug_4、mug_5、mug_7 不变，mug_9 上升（0.95 → 0.97）；闭合轴误差 mug_4 +1.1°、mug_5 −0.2°、mug_7 +1.4°、mug_9 −1.7°，都在 13° 以内。没有变差到过不了线。

### 4.3 不确定的地方

- 办法是在看到 `mug_8` 不过线之后选的，每个办法只试了一次，没有扫参数（灵敏度只是事后的稳健性检查）。检查还是同一批 5 个留出实例，里面只有 `mug_8` 是伸出量特别大的；“对更多的把手形状也有用”没有验证（推断：对伸出量在源实例范围外的把手有用，因为它把伸出量拉回范围内）。
- 对齐把源实例的伸出量也拉成同一个值（0.48–1.18 → 0.92），这一步对其他 4 个实例有轻微影响，数字见上表。
- 闭合轴误差在 `mug_8` 上从 22.8° 降到 10.9°；**推断**：原来最近点找到的是离把手最近的杯身或把手根部的抓取，闭合方向不对；伸出量对齐后找到了把手上的抓取。没有单独验证。
- 没有多次随机种子：检查里没有随机采样，ICP 从固定初值出发。
