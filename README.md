# Affordance-aware VLA training

This repository holds the VLA direction of the affordance project: a training method for vision-language-action models in cluttered tabletop manipulation. The VLA predicts a contact–approach–waypoint plan, its actions are kept consistent with that plan during training, and a lightweight per-episode affordance state tracks objects that become occluded or are moved. The claim to test is higher closed-loop success in simulation than the same backbone trained the usual way, with fewer wrong-object, wrong-direction and collision failures.

Everything here is a research plan with data and label checks, one walk-through of the pipeline with a released open-source checkpoint, and a first diagnostic training run on top of that checkpoint (11 November 2026: does the action head follow a plan it is given?). The full method has not been trained yet.

On 10 November 2026 this repository was split from the `vla` branch of [affordance3D](https://github.com/zniihgnexy/affordance3D), with its full history. The environment-memory direction (`mem`) stays in affordance3D.

## Code

- `affordance_vla/sim/libero_io.py` reads LIBERO demonstration files and BDDL scene descriptions.
- `affordance_vla/plan/caw_labels.py` derives contact–approach–waypoint labels from end-effector paths and gripper commands, and checks how well summed actions track the path.
- `affordance_vla/plan/plan_consistency.py` compares the path an action chunk asks for with the plan still ahead; `affordance_vla/plan/episode_state.py` keeps one rule-based slot per object through an episode; `affordance_vla/analysis/rollout_outcome.py` labels a rollout from simulator grasp flags.
- `affordance_vla/plan/plan_input.py` turns a contact, an approach direction and the kind of gripper event into the plan input of the action head; `affordance_vla/training/counterfactual.py` and `affordance_vla/training/plan_samples.py` build training samples whose plan is moved elsewhere, from the demonstration tracks stored by `affordance_vla/training/plan_dataset.py`; `affordance_vla/training/path_loss.py` is the plan–action consistency loss; `affordance_vla/heads/lora.py` and `affordance_vla/heads/plan_policy.py` put the plan input and low-rank updates on the released action head; `affordance_vla/analysis/plan_stages.py` splits a rollout into reached, held and delivered; `affordance_vla/training/plan_targets.py` and `affordance_vla/heads/plan_predictor.py` train a small readout of the VLM that predicts the plan; `affordance_vla/sim/benchmark_text.py` gives the instruction of a perturbed LIBERO-PRO task. `affordance_vla/heads/plan_grid.py` is the plan head that scores the image cells of the agent view; `affordance_vla/plan/plan_hold.py` keeps a predicted plan until its gripper event; `affordance_vla/analysis/plan_audit.py` tells which object each logged plan pointed at.
- `affordance_vla/sim/rollout_log.py` reads the per-step episode logs and `affordance_vla/sim/libero_camera.py` projects world points into the image the policy sees and lifts a depth image back to world points; `affordance_vla/plan/affordance_map.py` builds an affordance map from simulator ground truth and gives the 3D point a map stands for.
- `report/vla_report_helpers.py` and `scripts/report/build_vla_report.py` build the datasets report; `report/vla_pipeline_demo_helpers.py`, `report/vla_pipeline_demo_labels.py` and `scripts/report/build_vla_pipeline_demo.py` build the pipeline demo; `report/plan_following_helpers.py`, `scripts/report/build_plan_following_report.py` and `scripts/report/conclusions_plan_following.md` build the plan-following notebook; `report/affordance_pipeline_helpers.py`, `scripts/report/build_affordance_pipeline_walkthrough.py` and `scripts/report/conclusions_affordance_pipeline.md` build the walk-through. `report/libero_pro_helpers.py`, `report/plan_predictor_helpers.py` and `report/task_perturbation_helpers.py` with `scripts/report/build_libero_pro_report.py`, `scripts/report/build_plan_predictor_report.py`, `scripts/report/build_libero_pro_full_report.py` and `scripts/report/build_task_perturbation_report.py` build the LIBERO-PRO notebooks.
- `scripts/remote/` sets up the starVLA training stack and the LIBERO simulator on the A6000 server, and holds the probe, rollout, training and evaluation scripts that go through the GPU queue.
- **Working copy:** since 10 November 2026 the working copy is `~/affordance-vla` on the A6000 server, with data, models and outputs on the NAS; the layout is in the V0 server setup record.
- **Environment:** on the server, the starVLA env built by `envs/server/setup_starvla_env.sh`. [`envs/legacy/requirements_mac_e0.txt`](envs/legacy/requirements_mac_e0.txt) is the earlier Mac environment. Run the tests with `python -m pytest`.
